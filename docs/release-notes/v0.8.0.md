# v0.8.0

Changes since v0.7.0 (2026-10-24). The full list is `git log v0.7.0..v0.8.0`; every tool and flag below is described in [REFERENCE.md](../../REFERENCE.md).

## New

- **Python and C#.** Tree-sitter profiles for Python (`.py`, `.pyi`) and C# (`.cs`), with the grammars vendored under `vendor/`. Both have cross-reference facts, and `emetgate_rename` takes a Python or C# file.
- **`emetgate_edit` and `emetgate_write`.** Replace an exact `old_string` with `new_string` in any file, or create or overwrite a whole file, through the same gate as `emetgate_try`.
- **`emetgate_git_write`.** Git writes through a per-subcommand flag list, including `init`, `clone` and `remote`; forms that discard work or rewrite a remote need `force:true`.
- **`emetgate_commit` and `emetgate commit -m <message>`.** Commits the pending gated writes as one commit built from HEAD, with a receipt note attached, so `emetgate verify --branch` can return `verified`. Refused, naming the files, if a file changed outside the gate.
- **Symbol-level `emetgate_git`.** `diff` and `show` report which symbols changed and answer compactly under the read budget by default (`detail:"full"` for every hunk); new `blame` subcommand maps each symbol to the commit that last changed it.
- **Toolchain commands in `emetgate_run`.** An install, build or check with npm, pnpm, yarn, bun, pip, uv, dotnet, cargo or go runs in the repository without an allowlist entry; when it changes files the reply carries a receipt.
- **Batch retry.** After a failed `emetgate_try_batch`, send `retry` with only the items of the files you change.
- **Rule catalog.** `/rule pick` selects rules from a catalog, and `emetgate rules` opens an interactive checklist; the catalog has language-aware entries.
- **`emetgate doctor`** checks claude, git, the test command and the sandbox before a first lockdown, and [docs/QUICKSTART.md](../QUICKSTART.md) walks through install, doctor and lockdown.
- **Lockdown without `.mcp.json`.** When the directory has none, lockdown writes its own config, in its state directory, that serves the running emetgate; nothing is written into the repository.
- The gate shadow lists untracked files git does not ignore, leaving out build and cache folders such as `node_modules`, `bin`, `obj`, `target` and `.venv`.
- `emetgate --version` and `emetgate help`.
- **Bounded caches.** The find, index, facts and shadow caches are swept once a day: an entry whose repository is gone or that was unused for 30 days is removed, and above 5 GB the least recently used go first. An entry a running emetgate holds, or with a file still open, is kept. `emetgate recover` sweeps now; `--cache-max-age-days` and `--cache-max-mb` set the limits.

## Fixed

- `emetgate --version` reports the release version; v0.7.0 reported 0.6.1, and a release whose tag differs from the build version is now refused.
- A `emetgate_try_batch` that creates the project file (for example `pyproject.toml` or `package.json`) in an empty folder runs the test command it names, instead of landing as `unverified_no_tests`.
- Test builds keep their caches in a per-run temporary folder, so running the suite no longer fills `%LOCALAPPDATA%\emetgate`.
- `emetgate_find`, `emetgate_evidence` and `emetgate_explore` see a write made through emetgate, or by an editor outside it, on the very next call.
- A kept shadow or cache whose owner rights withhold relabelling (for example one owned by Administrators) is replaced or rebuilt so the sandbox still runs confined; a shadow root that can never be labelled is refused with `LabelDenied` and a fix naming the folder.
- Shadow workspaces are cleaned up on every exit, and stale ones left by gone repositories are swept.
- JSON input with a lone surrogate escape is accepted (decoded as U+FFFD) instead of being refused, including in the `/rule` prompt hook.
- The symbol mapper no longer crashes on a binary or pure-rename diff.
- Child processes are bounded: every git child has stdin closed, runs in a job that is killed on return, and is stopped after 120 s (180 s for `fetch`, `pull` and `push`).

## Changed

- The find index build reads files and builds its wavelet trees in parallel; the output is byte-identical.
- Search result assembly counts matches more cheaply once the hit cap is full; the certified output is unchanged.
- CI: ripgrep is installed from its GitHub release, the nightly jobs run in parallel with timeouts taken from measured run times, a stale doc check fails the build, and a guard rejects commits with a disallowed author email or attribution trailers.
